# rCore Lab 2：虚拟内存、用户指针与 mmap

## 1. 实验目的

本实验在 ch3 多道程序系统的基础上引入 Sv39 分页机制，为每个用户任务建立独立地址空间；实现安全的用户指针读取和写入，完成 `get_time`、`trace`、`mmap` 与 `munmap`，并验证用户态不能绕过页表权限直接访问内核或其他未授权内存。

## 2. 实验环境

- Windows + WSL2 + Ubuntu 20.04
- Rust `nightly-2024-05-02`
- `riscv64gc-unknown-none-elf` 目标
- RustSBI 0.4.1
- QEMU 11.1
- rCore-Tutorial ch4 作业分支

## 3. 地址空间设计

每个 `TaskControlBlock` 持有独立的 `MemorySet`。`MemorySet` 由根页表和一组 `MapArea` 组成，其 `token()` 将根物理页号编码为 Sv39 的 satp 值。任务切换时，Trap 返回路径使用当前任务的 token 恢复用户页表，因此不同任务看到的是彼此隔离的虚拟地址空间。

内核地址空间 `KERNEL_SPACE` 采用恒等映射，把内核代码、只读数据、可写数据、BSS 和可用物理内存映射到相同虚拟地址；每个任务另有独立的内核栈。用户 ELF 的各 Load 段按程序头映射到低半区，并设置相应的 `R/W/X/U` 权限；用户栈带保护页。Trampoline 和 TrapContext 位于高地址固定区域，使用户态 Trap 能在切换页表的过程中继续执行。

## 4. 用户指针翻译与安全复制

内核不能信任用户传入的裸指针。`translated_byte_buffer` 和 `translated_byte_buffer_mut` 以当前任务 token 构造临时页表视图，逐页调用 `translate` 找到 PTE，再检查页面有效性和读写权限。每个连续片段只覆盖当前页内的有效字节，因此缓冲区跨页时仍能正确读写。

为避免把用户长度当作内核分配大小，复制函数先使用 `checked_add` 计算结束地址，并要求地址始终位于用户低半区 `[0, 0x8000_0000)`。之后才按实际页数建立切片。`copy_from_user` 与 `copy_to_user` 在此基础上完成内核缓冲区和用户内存之间的复制；地址非法、未映射或权限不足时返回失败。

`sys_get_time` 先把时间写入内核栈上的 `TimeVal`，再安全复制到用户地址。`sys_trace` 的请求 0、1 分别读取和写入一个用户字节，请求 2 查询当前任务的系统调用计数。计数在 Trap 分发系统调用之前更新，因此查询 trace 自身时也已经包含本次调用。

## 5. sbrk、mmap 与 munmap

`sbrk` 在 ELF 末尾保留一个可扩展的堆区域。正增长时从旧 program break 映射新页，负增长时解除新增页并回收物理帧；新 break 不能低于初始堆底。

`mmap(start, len, prot)` 要求起始地址页对齐、长度非零、`prot` 只包含读、写、执行三个合法位，并且至少包含一种权限。内核检查 `start + len` 不溢出且不超过用户地址空间上界，再把权限转换为页表标志并加上 `U` 位。映射前遍历现有 `MapArea`，用页号区间判断是否重叠；合法时创建匿名 `Framed` 区域并立即分配物理页。

`len` 不要求页对齐，最终范围由 `MapArea::new` 向上取整到整页。这一点是 `ch4_unmap` 中再次执行 `mmap(start - len, len + 1, prot)` 所要求的。`munmap` 则要求页对齐，并且只释放起止页号与某个完整映射区域完全一致的区间，从而拒绝非对齐长度或部分释放。

## 6. 测试结果

执行官方检查器：

```sh
make -C ci-user test CHAPTER=4
```

输出包含 `Test 04_1 OK!`、`Test 04_4 test OK!`、`Test 04_5 ummap OK!`、`Test 04_6 ummap2 OK!` 和 `Test trace_1 OK!`。两个只读映射越权写入用例按预期触发 PageFault，没有输出失败标记。检查器最终结果为：

```text
Test passed: 16/16
```

## 7. 遇到的问题与解决方法

第一次实现 `mmap` 时误要求 `len` 页对齐，导致合法的 `len + 1` 用例被拒绝。阅读 `ch4_unmap` 后改为只要求起始地址对齐，由映射区域负责向上取整。

随后完整测试在 `trace_read(isize::MAX)` 处申请 16 MiB 内核堆并失败。根因是 `VirtAddr` 只保留 Sv39 的低 39 位，超大的无效指针被截断后可能误命中页表结构，并产生异常大的页计数。修复方法是在用户缓冲区翻译前检查地址上界，并用加法检查防止长度溢出。修复后 16 项检查全部通过。

## 8. 实验总结

本实验把系统调用参数从普通整数变成了必须经过验证的用户地址。实现时既要完成页表翻译，也要检查地址范围、映射状态和 `R/W/X/U` 权限；任何一处缺失都可能让用户程序读写内核或使内核自身崩溃。独立地址空间同时简化了任务间隔离，但要求切换任务时同步切换 satp。最终实现通过了 16/16 官方检查，加深了我对 Sv39、跨页复制以及匿名映射生命周期的理解。
